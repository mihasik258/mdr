## О микроконтроллере

MDR1206FI — RISC-V микроконтроллер для **счётчиков электроэнергии и устройств измерения параметров электросети**. Ключевая особенность: встроенный блок **24-битного сигма-дельта АЦП на семь каналов** (4 канала тока + 3 канала напряжения), который аппаратно считает действующие значения и активную мощность.

| | |
|---|---|
| Ядро | **BM-310S0**, RISC-V **RV32IMCNZX**, 3-стадийный конвейер, режимы `machine`/`user` |
| Макс. частота | **50 МГц** (CHIP_ID = 217) / **42 МГц** (CHIP_ID = 215) |
| Flash | 2 × 256 Кбайт + 2 × 8 Кбайт информационной (217); 512 Кбайт + 15 Кбайт (215) |
| Корпус | **QFN88 10×10×0,75 (0,4)** |
| Питание | VCC/VCCA/VCCB **1,8…3,6 В**; для АЦП **VCCA = 3,0…3,6 В** |
| Температура | −50…85 °C (MDR1206FI/AFI), −40…85 (MDR1219LGI), 0…85 (MDR1215LGI) |
| Криптография | Аппаратное ускорение ГОСТ (расширение `xgost`) |

## Самые важные грабли

Собранный список того, на чём чаще всего спотыкаются. Подробности — по ссылкам.

| Ловушка | Где |
|---|---|
| Переключение режима загрузки не действует, пока установлен бит `FPOR` — режим читается из `BKP_LDO`, а не с выводов | [MDR1206FI.md, 6.1](MDR1206FI.md#61-как-определяется-режим-запуска) |
| Код операций с Flash **обязан** исполняться из ОЗУ (атрибут `__RAM_TEXT_NOINLINE`) | [MDR1206FI.md, 7.3](MDR1206FI.md#73-последовательности-операций-chip_id--217) |
| Flash: **не более 2 записей** в одну ячейку без стирания; `Thv ≤ 16 мс` на строку | [MDR1206FI.md, 7.3](MDR1206FI.md#73-последовательности-операций-chip_id--217) |
| При смене частоты ядра надо править `Delay[2:0]` в `FLASH_CMD`, иначе выборка мусора > 25 МГц | [MDR1206FI.md, 7.1](MDR1206FI.md#71-chip_id--217-mdr1206fi-mdr1215lgi-mdr1219lgi) |
| Бит `PORT_PWR` **инвертирован** между CHIP_ID = 217 и 215 | [MDR1206FI.md, 10.2](MDR1206FI.md#102-регистры-портов-таблица-330-с-213) |
| Защита Flash не покрывает дубль-диапазон `0x10080000`–`0x1FFFFFFF` — нужен PMP | [MDR1206FI.md, 7.6](MDR1206FI.md#76-слово-защиты-flash-памяти) |
| Программирование OTP **необратимо блокирует JTAG** | [MDR1206FI.md, 7.8](MDR1206FI.md#78-регистры-контроллера-flash-таблица-19-с-69) |
| IWDG не настраивается без работающего LSI и переживает внешний сброс | [MDR1206FI-05](MDR1206FI-05-DMA-прерывания-сторожевые.md#iwdg--независимый-сторожевой-таймер-с-430433) |
| DMA обнуляет `cycle_ctrl` после завершения цикла — дескриптор нужно переписать | [MDR1206FI-05](MDR1206FI-05-DMA-прерывания-сторожевые.md#структура-управляющих-данных-канала-с-378) |
| Ошибку DMA нельзя узнать напрямую: номер канала вычисляется методом исключения | [MDR1206FI-05](MDR1206FI-05-DMA-прерывания-сторожевые.md#порядок-обработки-ошибки-dma-с-378) |

| Выполнение из **TCM быстрее в 1,7 раза**, чем из Flash (3,7 против 2,15 Coremark/MHz) | [MDR1206FI-06](MDR1206FI-06-электрика-корпус-заказ.md#таблица-612--производительность-в-coremark) |

## Ограничения

Разделы, помеченные `⚠️` внутри документов, перечисляют места, где данные неполны — с указанием страниц исходного документа. Сводка наиболее существенных ограничений — в [NOTICE.md](NOTICE.md).

Кратко: не воспроизведена **графика спецификации** (блок-схемы, временные диаграммы — они доступны только в официальном PDF), **CSR-регистры RISC-V** (это стандарт, а не специфика Миландра) и построчные описания части регистров USART.

## Как это делалось

Текст извлечён из официальных PDF двумя способами:

1. **Плоскостной разбор** — быстрый, но теряет границы столбцов таблиц.
2. **Координатный разбор** — слова кластеризуются по `y` в строки, затем по `x` в колонки. Это позволило восстановить таблицы, которые плоскостной разбор «терял».

Скрипт координатного разбора: [`tablex.py`](tablex.py).

Отдельно проверено **пословно по всему документу**, где спецификация ссылается на errata — оказалось, что в шести местах, а не в одном.
